# Task Manager с фоновыми задачами и уведомлениями

> Backend pet-проект для портфолио Python Backend Developer

Рабочее название проекта: **TaskFlow**

---

## 1. Цель проекта

Разработать backend-сервис для управления задачами с поддержкой:
- пользователей и проектов,
- задач и их статусов,
- дедлайнов,
- фоновых напоминаний.

Проект предназначен для демонстрации практических навыков backend-разработки с использованием FastAPI, Celery, Redis и PostgreSQL.

---

## 2. Технологический стек

- **FastAPI** — REST API
- **PostgreSQL** — основное хранилище данных
- **Redis**:
  - брокер сообщений для Celery
  - кеширование данных
- **Celery**:
  - фоновые задачи
  - отложенные задачи
  - периодические задачи (Celery Beat)
- **Docker / docker-compose** — локальный запуск проекта

---

## 3. Общая архитектура

- FastAPI обрабатывает HTTP-запросы
- PostgreSQL хранит пользователей, проекты, задачи и напоминания
- Redis используется:
  - как message broker для Celery
  - как кеш для часто запрашиваемых данных
- Celery worker выполняет:
  - отправку напоминаний
  - периодические проверки дедлайнов

- Задача может иметь дедлайн

- Пользователь может создать напоминание для задачи
- Напоминание отправляется в заданное время
- Отправка выполняется асинхронно через Celery

Реализация:
- Используется `eta` или `countdown` в Celery
- После успешной отправки `is_sent = true`

- Проверка задач с истёкшим дедлайном
- Отправка уведомлений о просроченных задачах (1 раз в день)

## 13. Telegram Bot интеграция

### 13.1 Цель
Предоставить альтернативный интерфейс для работы с TaskFlow через Telegram, а также основной канал для получения уведомлений.

### 13.2 Связь User ↔ Telegram

**Расширение таблицы User:**
- `telegram_id` (bigint, nullable, unique) — ID пользователя в Telegram
- `telegram_username` (string, nullable) — username в Telegram (@username)
- `telegram_notifications_enabled` (boolean, default: true)

**Процесс привязки аккаунта:**

Вариант 1 (через токен — РЕКОМЕНДУЕТСЯ):
1. Пользователь регистрируется через API
2. Получает одноразовый токен: `GET /api/telegram/generate-link-token`
3. Открывает бота в Telegram
4. Отправляет команду `/link <token>`
5. Backend связывает telegram_id с аккаунтом

Вариант 2 (прямая регистрация в боте):
1. Пользователь отправляет `/register <email> <password>` в бота
2. Backend создаёт аккаунт и сразу привязывает telegram_id
3. Можно потом авторизоваться через API с теми же credentials

**Безопасность:**
- Токен привязки должен быть одноразовым
- TTL токена: 5-10 минут
- Хранить в Redis: `link_token:{token}` → `user_id`

### 13.3 Архитектура

**Три возможных подхода:**

#### Вариант A: Отдельный сервис бота (рекомендуется)
```
taskflow/
├── src/              # FastAPI backend
├── bot/              # Telegram bot (отдельный процесс)
│   ├── main.py
│   ├── handlers/
│   │   ├── auth.py
│   │   ├── tasks.py
│   │   └── projects.py
│   ├── services/
│   └── keyboards/
└── docker-compose.yml
```

**Плюсы:**
- Чистое разделение ответственности
- Бот может работать независимо от FastAPI
- Проще масштабировать
- Можно переиспользовать модели и utils

**Минусы:**
- Больше кода
- Нужно организовать общение между сервисами

---

#### Вариант B: Интеграция в FastAPI
```
src/
├── api/
├── models/
├── telegram/         # Telegram bot внутри FastAPI
│   ├── bot.py
│   ├── handlers.py
│   └── services.py
└── main.py
```

**Плюсы:**
- Прямое переиспользование кода
- Один контейнер
- Прямой доступ к БД

**Минусы:**
- Смешивание HTTP и Telegram логики
- Сложнее тестировать

---

#### Вариант C: Webhook подход (production-ready)
- Telegram отправляет обновления на `POST /telegram/webhook`
- FastAPI обрабатывает как обычный HTTP эндпоинт
- Не требует отдельного polling процесса

**Требования:**
- Публичный HTTPS URL (для локалки: ngrok)
- Регистрация webhook: `setWebhook` в Telegram API

**Для учебного проекта:** Вариант A (отдельный сервис) + polling

### 13.5 Уведомления через Telegram

**Типы уведомлений:**

**1. Напоминание о задаче (Reminder)**
- Пользователь создал Reminder через API или бота
- В указанное время Celery запускает задачу отправки
- Сообщение отправляется в Telegram

**2. Просроченный дедлайн**
- Celery Beat периодически проверяет дедлайны
- Если задача просрочена и не `done` → уведомление
- Отправляется один раз (флаг `deadline_notification_sent`)

**3. Дедлайн приближается (опционально)**
- За 24 часа до дедлайна — предупреждение
- Можно настроить: за 1 час, 1 день, 1 неделю

**4. Ежедневный дайджест (опционально)**
- Каждое утро в 9:00: "Сегодня у тебя X задач"
- Можно настроить время отправки

**Формат сообщения:**

```
⚠️ Дедлайн истёк!

📋 Задача: "Написать README для проекта"
📁 Проект: TaskFlow Backend
⏰ Дедлайн был: 03.01.2026 18:00
📊 Статус: В работе

Действия:
/task_42 — посмотреть детали
/done_42 — отметить выполненной
```

**Inline кнопки (улучшенный UX):**
```
[Посмотреть] [✅ Выполнено] [🔔 Напомнить через 1ч]
```

### 13.9 Celery задачи для Telegram

**Новые или модифицированные задачи:**

**1. send_telegram_message(telegram_id, text, parse_mode='Markdown')**
- Базовая задача для отправки сообщения
- Обрабатывает ошибки (пользователь заблокировал бота)
- Логирует в NotificationLog

**2. send_telegram_notification(user_id, notification_type, data)**
- Универсальная задача для уведомлений
- Формирует текст сообщения в зависимости от типа
- Проверяет `telegram_notifications_enabled`

**3. check_deadlines_and_notify() (модификация существующей)**
- Находит просроченные задачи
- Для каждой задачи:
  - Создаёт NotificationLog
  - Если у user есть telegram_id и notifications enabled:
    - `send_telegram_notification.delay(user_id, 'deadline_overdue', task_data)`

**4. send_daily_digest() (периодическая, Celery Beat)**
- Запускается каждое утро (настроить в beat_schedule)
- Для каждого пользователя с telegram_id:
  - Собирает статистику задач
  - Отправляет дайджест

**Пример конфигурации Celery Beat:**
```python
celery_instance.conf.beat_schedule = {
    "check-deadlines": {
        "task": "check_deadlines_and_notify",
        "schedule": timedelta(hours=1),  # каждый час
    },
    "daily-digest": {
        "task": "send_daily_digest",
        "schedule": crontab(hour=9, minute=0),  # каждый день в 9:00
    }
}
```

### 13.11 Безопасность

**Обязательные меры:**

1. **Проверка прав доступа**
   - Всегда проверять, что telegram_id соответствует user_id
   - Пользователь может видеть только свои проекты/задачи

2. **Валидация команд**
   - Проверять формат всех входных данных
   - Защита от SQL injection (используя ORM)
   - Санитизация текста перед отправкой

3. **Rate Limiting**
   - Ограничение количества команд в минуту
   - Защита от спама/флуда

4. **Токены привязки**
   - Одноразовые токены с TTL
   - Хранить в Redis, не в БД
   - Не принимать пароли напрямую в боте

5. **Webhook безопасность** (если используется)
   - Проверка секретного токена в headers
   - Whitelist IP адресов Telegram

6. **Логирование**
   - Логировать все команды пользователей
   - Отслеживать подозрительную активность

### 13.17 Рекомендации по реализации

**Порядок разработки:**

**Этап 1: Базовая настройка**
1. Создать бота через @BotFather
2. Настроить структуру папок (`bot/`)
3. Подключить aiogram
4. Реализовать команду `/start`

**Этап 2: Аутентификация**
1. Добавить поля `telegram_id` в User модель
2. Создать эндпоинт генерации токена привязки
3. Реализовать команду `/link`
4. Тестировать привязку аккаунта

**Этап 3: Просмотр данных**
1. Команды `/projects`, `/tasks`
2. Форматирование сообщений
